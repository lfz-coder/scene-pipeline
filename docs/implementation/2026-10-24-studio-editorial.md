# 第六篇的写作判断

- 核心立场：先用 OpenAPI 固定模型服务边界，再用可运行的本地执行器验证人工确认与时间线；Go handler 可以后接，客户端不能因此只剩空按钮。
- 两个误解：写出 JSON 文档就等于契约已生效；预览滑杆在移动就等于视频已经解码成功。
- 本机证据：规范拒绝 VLM 空附件；取消后迟到结果不能入轨；真实 H264 帧变化与相同视频 100 ms 跳切通过回归；工程取消状态恢复错误曾被测试复现并修正。
- 使用边界：适合单人本地创作与后续 Go 接入；不适合作为多轨剪辑、音画同步或分布式任务平台的完成证明。轮询比流式推送简单，但长文本首字延迟更高。
- 可带走的产物：四接口 OpenAPI、Go 模块约束、独立 TimelineModel、可复用 AIService、真实窗口测试命令。
- 论证顺序：运行一条完整流程 → 看模块和契约 → 解释人工确认 → 解释媒体时间映射 → 展示测试发现的错误 → 后端接入边界。
- 价值检查：读者能在今天运行软件，并在接 Go 前检查自己是否误把供应商 API 当业务 API，是否遗漏取消协调、版本冲突和媒体源区间。
