## 中文文章更新判断

核心立场：先把已存在的两条调用路径（交互面板、无窗口参数操作）落到同一个控制器，再在真实资源切换点引入工厂；这样能复用当前代码，又不预写 AI 任务框架。

需要拆开的两个误解：MVC 目录不自动阻止 UI 写 GPU；抽象工厂不自动完成 Qt 的上下文 / FBO / 生命周期适配。

证据计划：现有场景可运行；新增 CPU 控制器例子；注入工厂缓存/失败释放测试；保留实际 GPU 像素和生命周期回归。完成后用实际结果替换验证记录。

取舍：多一层稳定接口换取第二调用方和实现替换；只覆盖现有 Shader/Mesh/Texture，不包装所有 GL API，不提前做 AI 节点图。文章沿“直接编辑的局限 → 模型与操作分离 → 第二调用方 → 宿主与资源适配的剩余工作”论证。
